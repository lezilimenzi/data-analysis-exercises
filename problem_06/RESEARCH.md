## 최종 요약 (2026-10-05)

### A. 최종 채택 모델: Cthr
| 구성 요소 | 설정 | 역할 |
|---|---|---|
| 표현 | `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,5), sublinear_tf=True, min_df=2)` | 단어 경계 안의 연속 문자 2~5개 조각을 특징으로 쓴다. 전화번호·단축번호(`08712…`, `86688`), 통화·과금 문구(`£`, `150p`, `/msg`), 축약어(`txt`, `2nite`)처럼 **단어 단위로는 잘 잡히지 않는 부분 문자열**을 그대로 특징으로 만든다. `sublinear_tf`는 같은 조각이 여러 번 나와도 영향이 과하게 커지지 않게 한다 |
| 분류기 | `LinearSVC(C=1, class_weight="balanced")` | 수만 차원의 희소 특징에서 스팸과 정상을 가르는 선형 경계를 학습한다. 스팸이 1/8뿐이라 클래스 균형 가중을 준다 |
| 결정 규칙 | `TunedThresholdClassifierCV`(내부 3-fold, macro F1, 후보 41개) | SVC 점수의 판정 기준을 0에서 스팸 쪽으로 옮긴다. 전체 train에서 고른 값은 −0.078이다. 기준값은 학습 데이터 안의 교차검증으로만 골랐다 |

- **이 모델이 맞았던 이유** [사실 + 추론]: 스팸의 핵심 신호가 번호·기호·과금 문구 같은 표면 문자열이었다(§3: 5자리 이상 숫자는 스팸 76%, 정상 0.06%). 문자 n-gram은 이 신호를 직접 특징으로 만들고, 선형 SVM은 그런 고차원 희소 특징에서 정밀도가 높았다. 학습은 몇 초면 끝나 30분 제한에도 맞았다.
- **임계값을 조정한 이유** [사실]: 기준 모델(A)의 오류가 거의 전부 놓친 스팸(FN 30)이었고, 오탐(FP 4)은 거의 없었다. 경계를 스팸 쪽으로 조금 옮겨도 오탐이 늘지 않을 여유가 있었다. 실제로 FN은 30 → 26으로 줄고 FP는 4 그대로였다(seed 2026 OOF).

### B. 채점 결과
| 항목 | 값 |
|---|---|
| **test macro F1** | **0.9812** (사용자 채점 1회) |
| 선택에 쓴 CV (seed 2026~2028, 15 fold 평균) | 0.9832 (fold 표준편차 0.0065) |
| A 대비 짝지은 차이 (선택 근거) | +0.0015, 개선 8 / 악화 3 / 동점 4 |
| 제출 파일 생성까지 걸린 시간 | 약 23분 (노트북 실행 65초) |

- test가 CV보다 0.002 낮고 fold 표준편차 범위 안이다. 선택에 쓴 점수의 낙관 편향, test 표본 변동과 일관된다 [추론].
- 임계값 조정 전 모델(A)은 채점하지 않았으므로, test에서 임계값 조정이 기여했는지는 알 수 없다.
- 채점 후 사후 실험에서 채택 규칙을 통과한 것은 class_weight 제거(K1)뿐이었다. SVC C=3은 개정된 규칙으로만 통과하는 사후 판정이다(EXPERIMENTS Run 4). 하지만 전체 학습 후 test 예측이 제출과 1,000행 모두 같았다. 정답이 아니라 예측끼리 비교한 결과다(`EXPERIMENTS.md` Run 10).

### D. 접근 방식
```
1. EDA (§1~4)        분포·표면 특징·정규화 템플릿 중복·train–test 차이
2. 기준선 (§5)        단어 / 문자 n-gram × NB / LR / SVC를 같은 분할에서 비교 → 문자 n-gram + SVC
3. 오류 분석 (§6)     FN과 FP 비대칭, 모델 공통 오류, 놓친 스팸을 직접 읽고 유형 분류
4. 후보 탐색 (§7)     약점(경계 근처 FN)을 겨냥한 소수 후보: 임계값, 단어+문자, 메타 특징, 노이즈 필터링
5. 계획 (PLAN.md)     후보 3개 고정, 채택 규칙 사전 고정, 탐색과 다른 seed로 판정, 안전 제출본 먼저
6. 구현 (노트북)      안전 제출본 → 15 fold 짝지은 비교 → 규칙으로 Cthr 선택 → 전체 재학습 → 형식 검사
7. 사후 실험          채점 후 실험으로 제출은 바꾸지 않음 (EXPERIMENTS.md Run 4, 6~12)
```

과적합을 피하려고 지킨 원칙:
- 임계값·가중치·설정은 모두 **바깥 fold의 학습 부분 안에서만** 골랐다(중첩 CV).
- 후보를 고른 탐색 분할(seed 42~44, 100~102)과 채택을 판정한 분할(seed 2026~2028)을 나눴다. 다만 같은 데이터를 다시 나눈 것이라 독립 평가는 아니다.
- 채택 규칙을 결과를 보기 전에 PLAN.md에 적었다.
- test 점수로 모델을 다시 고르지 않았다.

## 1. 제공 파일과 환경 [사실]

- 결측 없음. sample의 ID 순서 = test 순서.
- `requirements.txt`: pandas, scikit-learn, notebook. 설치 버전 sklearn 1.7.2(`TunedThresholdClassifierCV` 사용 가능), nbconvert 7.17.1, ipykernel 있음. CPU 8코어.

## 2. 타깃 분포 [사실]
- 정상 3502 (87.5%) / 스팸 498 (12.5%). 지표가 macro F1이라 스팸 F1이 점수의 절반을 차지한다.

| 특징 | 스팸 | 정상 |

| 길이 중앙값 | 148자 | 52자 |
| 숫자 개수 평균 | 15.5 | 0.3 |

## 4. 중복·누수 [사실]
- 완전 중복: train 안 0건, train–test 0건.
- 숫자→`0`, 문장부호 제거로 정규화한 "템플릿" 기준: train 안 중복 37건(주로 스팸), test 14건이 train 템플릿과 같다. 정규화 그룹 안의 라벨 충돌 0건.
- 템플릿 단위 Group CV와 일반 층화 CV의 점수 차이는 반복 간 흔들림 수준이었다(§5). → **층화 CV를 써도 낙관 편향이 작다** [사실, 이 후보들에 한해].

## 5. 기준선 비교 [사실, 탐색용 점수]
5-fold × 3회 반복 OOF macro F1 (pooled, 반복 평균). 하이퍼파라미터는 고정값이고 탐색하지 않았다.
- 분할: `StratifiedKFold(5, shuffle=True, random_state=42+r)`, r = 0..2 (템플릿 Group CV는 `StratifiedGroupKFold` 같은 seed).
- 설정 (2026-10-05 보충, 재현에 필요): NB = `TfidfVectorizer(ngram_range=(1,2))` + `MultinomialNB(alpha=0.1)` / word = `TfidfVectorizer(ngram_range=(1,2), sublinear_tf=True, min_df=1)` / char = `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,5), sublinear_tf=True, min_df=2)` / LR = `LogisticRegression(C=10, max_iter=3000, class_weight="balanced")` / SVC = `LinearSVC(C=1, class_weight=...)`. 이 설정으로 아래 pooled 점수를 재현했다(`posthoc_extra.py` R1).

| 후보 | 층화 CV | 템플릿 Group CV | OOF 혼동 [TN FP FN TP] (1회) |
|---|---|---|---|
| word(1-2) TF-IDF + MultinomialNB | 0.956 | 0.955 | 3500 2 71 427 |
| word(1-2) TF-IDF + LR(balanced) | 0.961 | 0.963 | 3468 34 33 465 |
| char_wb(2-5) TF-IDF + LR(balanced) | 0.980 | 0.980 | 3497 5 29 469 |
| **char_wb(2-5) TF-IDF + LinearSVC(balanced)** | **0.981** | **0.980** | 3499 3 30 468 |
| word + char + LinearSVC(balanced) | 0.980 | 0.981 | 3500 2 30 468 |
| word + char + LinearSVC(가중치 없음) | 0.979 | 0.980 | 3500 2 34 464 |

- **문자 n-gram이 단어 n-gram보다 뚜렷이 좋다.** 전화번호·단축번호·£·`p/txt` 같은 부분 문자열 패턴을 잡기 때문으로 본다 [추론].
- 5-fold 1회 학습·예측은 후보당 2~3초 수준이다.

## 6. 가장 예측이 안 되는 부분: 오류 분석 [사실 + 추론]
char SVC OOF 오류는 **FN 28~30건(놓친 스팸) 대 FP 2~3건**으로 거의 전부 스팸 recall 쪽이다.

놓친 스팸 28건의 특징 [사실]:
- 5자리 이상 숫자가 있는 건 3건뿐이다. 나머지는 **전화번호·단축번호가 없는 스팸**이다.
- 4개 모델(word LR, char LR, char SVC, word+char SVC)이 공통으로 놓친 건이 22건이다. → 모델을 바꿔서 해결되는 오류가 아니다.

| 과금 문구가 짧게 붙은 경우 | "…msgs cst std ntwk chg £1.50", "enjoy @ one gbp/sms" | 중간~높음. 결정 경계 근처일 가능성 |

FP 2건: 정상 대화와 `www.fullonsms.com` 알림. 정상 쪽 오류는 거의 없다.

**시사점** [추론]
- 남은 오류 중 단서가 거의 없는 유형(구독 콘텐츠, 잘린 문장)은 맞히기 어렵다. 이것을 맞추려고 recall을 강하게 올리면 정상 메시지(FP)가 늘어 과적합·악화될 위험이 크다. (2026-10-05 수정: 원래 "텍스트 정보의 한계다"로 단정했다)
- 공략 가능한 부분은 **결정 경계 근처의 스팸**이다. FP가 거의 없으므로 결정 임계값을 스팸 쪽으로 약간 옮기는 것이 가장 싼 레버다.

## 7. 개선 후보 탐색 [사실, 탐색용]
5-fold × 3회 = 15 fold의 짝지은 비교. 기준은 char SVC(A). 임계값은 각 바깥 fold의 학습 부분 안에서 `TunedThresholdClassifierCV`(내부 3-fold, macro F1)로 골랐다(중첩).

| 후보 | fold 평균 | A 대비 짝지은 차이 | 개선/악화 fold |
|---|---|---|---|
| A char SVC | 0.9814 | — | — |
| B char SVC + 메타 특징 5개(길이·숫자 수·5자리 숫자·통화·대문자 비율) | 0.9762 | −0.0051 | 3 / 10 → **악화** |
| C char SVC + 임계값 조정 | 0.9822 | +0.0008 | 9 / 5 |
| D char LR + 임계값 조정 | 0.9792 | −0.0022 | 6 / 7 |
| E word+char SVC + 임계값 조정 | 0.9827 | +0.0014 | 10 / 3 |

- 노이즈 필터링 (사용자 질문 후 추가, seed 2026~2028, 15 fold): 바깥 fold 학습 부분의 내부 OOF에서 라벨과 반대쪽으로 분류된 샘플(margin < 0, 평균 28건 중 스팸 26건)을 빼고 재학습 → A 대비 **−0.0031, 개선 1 / 악화 11 → 악화**. margin < −0.5만 제거(평균 12건)해도 −0.0020, 1 / 9 → **악화**. 평가 라벨은 손대지 않았다.
- 메타 특징은 char n-gram과 정보가 겹치고, 스케일이 다른 dense 열이 SVC 경계를 흔든 것으로 본다 [추론]. → 제외.
- C·E는 **소폭 개선 또는 개선 근거 부족** 수준이다. 차이가 fold 표준편차(약 0.007)보다 훨씬 작다.
- 이 표는 후보를 고르는 데 이미 썼으므로, 최종 채택 판정은 **다른 분할 seed**로 다시 해야 한다(PLAN §4).
- 전체 train에 대해 C를 학습하는 시간은 약 2초였다. 고른 임계값(SVC decision 기준) −0.08은 기본값 0에서 스팸 쪽으로 약간 옮긴 값이다.
