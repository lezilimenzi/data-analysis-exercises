# Problem 05 — 30분 제한 구현 계획

작성일: 2026-10-01. 상태: 사용자 승인 후 최소 기준 모델 구현·실행 완료. 실제 결과는 EXPERIMENTS.md 참고.

## 1. 목표와 승인 범위

제공 특징 + 규제 분류기부터 비교하고, 실제 개발 OOF 오류를 근거로 제한적인 보완을 검증한다. 최종 산출물은 실행 결과가 포함된 `solution.ipynb`, `submission.csv`다. 구현은 이 계획의 사용자 승인 후 시작한다.

현재 완료: EDA, 10장 encoder 동작 확인, 연구·계획 문서 작성. 미완료: 전체 특징 추출, 분류기 학습·비교, 노트북·제출 생성.

## 2. 검증 설계

- 클래스 목록 [0,1,2,3,4], seed=42 고정.
- 750장 중 층화 분할로 개발 600장(각 120), 최종 확인 150장(각 30)을 고정한다.
- 개발 600장 안에서 StratifiedKFold(3, shuffle=True, random_state=42): fold별 학습 400장, 검증 200장. 모든 후보에 동일 인덱스를 사용한다.
- 모델 선택 지표는 개발 600장의 pooled OOF Macro-F1. fold 점수 3개, 클래스별 precision/recall/F1, 혼동행렬, 학습 시간도 기록한다. pooled 점수와 fold 평균을 혼용하지 않는다.
- encoder는 고정이므로 전체 특징 선추출 허용. StandardScaler는 fold 학습 데이터만 fit, Normalizer는 각 이미지 벡터를 L2 정규화한다. 보조 특징의 스케일러도 fold 내부에 둔다.
- 후보와 보완안 선택을 끝내고 설정을 잠근 다음 개발 600장으로 fit하여 확인 150장을 정확히 한 번 평가한다. 이 점수로 후보 재선택·되돌리기·추가 튜닝하지 않는다. 낮으면 그대로 한계를 보고한다.
- 마지막에는 같은 설정으로 전체 750장에 전처리와 분류기를 다시 fit하여 test 예측한다.
- holdout 표본이 작고 전체 EDA에 이미 포함되어 있으므로 정밀한 독립 일반화 성능이라고 과장하지 않는다. 지리 그룹 정보 부재도 명시한다.

## 3. 최소 비교: 최대 6개 설정, 18회 CV fit

공통: StandardScaler → Normalizer(L2) → 분류기. class_weight=None, 불필요한 확률 보정 없음.

| 실행 순서 | 분류기 | 후보 설정 |
|---|---|---|
| 1 | LogisticRegression | L2, C=1, lbfgs, max_iter=2000 |
| 2 | LinearSVC | L2, C=0.1, dual=auto, max_iter=5000, random_state=42 |
| 3 | SVC | RBF, C=1, gamma=scale, probability=False |
| 4 | LogisticRegression | C=10, 나머지 동일 |
| 5 | LinearSVC | C=1, 나머지 동일 |
| 6 | SVC | C=10, 나머지 동일 |

먼저 각 종류의 기본 후보를 비교하고 잔여 시간에 따라 4~6을 생략한다. 후보 하나는 동일 3개 fold를 모두 완료해야 순위에 포함한다. 수렴 경고가 있으면 결과에 표시하고, 예산 내에서 max_iter만 한 번 늘려 확인한다. 미수렴 후보를 검증된 승자로 보고하지 않는다.

선택: 최고 pooled OOF 점수에서 0.005 이내인 후보는 단순성 우선으로 LogisticRegression → LinearSVC → RBF SVC, 같은 종류에서는 작은 C 순으로 선택한다. 0.005는 추가 복잡도를 제한하는 운영상 허용 차이이며 통계적 동등성 기준이 아니다. 최고 점수 후보와 실제 선택 후보를 모두 기록한다.

## 4. 약점 진단과 보완: 특징 묶음 하나만

### 4.1 기준 후보의 개발 OOF 오류 확인

- 최저 F1 클래스, 가장 많은 양방향 혼동 쌍, FN/FP의 방향을 확인한다.
- 낮은 점수가 3개 fold 중 적어도 2개에서 반복되는지 확인한다. fold 불안정성은 유의성 검정으로 해석하지 않는다.
- 학습 데이터의 해당 OOF 오분류 예시를 최대 12장 확인한다. 확인용 150장과 test의 오류·라벨을 분석에 사용하지 않는다.
- 색·질감 혼동으로 설명할 근거가 없거나 시간 여유가 없으면 보완을 생략한다. 약점이 처음 예상한 2↔3, 1↔3이 아닐 수도 있다.

### 4.2 조건부 보완 후보

64×64 원본에서 정답 없이 이미지별 12개 수치를 계산한다.

- RGB 채널별 평균·표준편차: 6개.
- HSV의 S,V 채널별 평균·표준편차: 4개. H는 원형 변수여서 이번 단순 요약에서 제외.
- RGB 평균 회색조(0~1)의 가로·세로 인접 픽셀 절대 차이 평균: 2개.

제공 1280차원 블록과 보조 12차원 블록을 각각 fold 내부 StandardScaler → L2 Normalizer 처리한다. 제공 블록 가중치 1, 보조 블록 가중치 0.25로 연결한다. 보조 특징이 거리를 지배하지 않게 하는 고정 설계이며 최적 가중치라는 뜻은 아니다. 새 특징 추가 후 C/gamma/블록 가중치 재탐색은 하지 않는다. gamma=scale인 RBF의 실제 값은 입력 변화에 따라 자동으로 달라질 수 있음을 기록한다.

기준에서 선택한 분류기 하나만 같은 3-fold로 추가 평가한다. 다음을 모두 만족하면 채택한다.

1. pooled OOF Macro-F1이 기준보다 0.005 이상 상승.
2. fold Macro-F1이 3개 중 적어도 2개에서 상승.
3. 추가 실험 전에 지정한 약한 클래스(또는 혼동 쌍의 평균) pooled F1이 상승.
4. 어느 클래스도 pooled F1이 0.03 넘게 하락하지 않음.

이 문턱은 소수 실험에서 손해와 복잡도를 제한하기 위한 운영 규칙이다. 통계적 유의성·일반화 보장이 아니다. 실패하면 원래 특징을 유지하고 특징 종류를 바꾸며 반복 탐색하지 않는다. 계획대로 생략한 실험은 미실행이라고 기록한다.

## 5. 전체 30분 시간표와 중단 규칙

아래는 처음부터 끝까지의 상한 배분이다. 이미 쓴 시간을 차감하며 구현 승인 시 타이머를 재설정하지 않는다.

| 단계 | 배분 |
|---|---:|
| EDA | 4분 |
| 전략·문서·검토 | 5분 |
| 노트북 작성·환경 점검·전체 특징 추출 | 5분 |
| 기본 분류기 비교 | 6분 |
| 오류 진단·조건부 특징 보완 | 3분 |
| 잠근 모델 확인 평가·전체 학습·제출·노트북 저장 검증 | 5분 |
| 예비 시간 | 2분 |

- 사용자에게 실제 시작 시각/남은 시간을 요청했다. 회신 전에는 정확한 마감 준수를 확약하지 않는다. 현재 누적 시간과 잔여 시간 미확인 상태를 실행 시 해소해야 한다.
- 검토 대기까지 포함한 실제 시간이 30분을 넘었다면 초과를 보고하고 제한 내 완료라고 주장하지 않는다.
- 남은 7분부터 새 실험을 시작하지 않는다. 후보 4~6 → 보조 특징 순으로 무리하게 진행하지 말고, 남은 예산이 부족하면 모두 생략한다.
- 새 후보 실행 전 예상 소요 시간이 남은 시간에서 최종 5분을 뺀 값보다 크면 생략한다. 추정치는 첫 후보 실측으로 갱신한다.
- 미실행 선택지보다 제출 생성과 실행된 노트북 저장을 우선한다. 전체 노트북을 처음 실행할 때 결과를 저장하며, 마감 직전 전체 재실행을 추가하지 않는다.
- 환경 문제가 발생하면 원인을 기록한다. 패키지 전체 업그레이드·장시간 설치로 예산을 소모하지 않는다. 해결되지 않으면 정상 완료로 보고하지 않는다.

## 6. 작성할 파일과 Notebook 셀 순서

- `solution.ipynb`: 신규 최종 코드. 기존 `problem.ipynb`와 `feature_helper.py`는 유지한다.
- `train_features.npz`, `test_features.npz`: 제공 helper의 선택적 캐시.
- `submission.csv`: 최종 예측. `data/sample_submission.csv` ID 순서로 저장한다.
- RESEARCH.md/PLAN.md: 승인 후 실제 점수·실행 시간·선택 결과·미실행 항목을 기록한다.

Notebook 순서(의사코드):

1. 환경/경로/총 마감 설정 → 데이터 명세 검사 → 고정 분할 생성.
2. 이미지·EDA 요약 표시 → 제공 특징 추출/캐시 확인.
3. 후보별 같은 3-fold 학습 → OOF와 시간 저장 → 선택 규칙 적용.
4. 개발 오류 진단 → 필요하고 시간이 있을 때 보조 특징 1회 비교.
5. 설정 고정 → 확인 150장 1회 평가 → 전체 750장 재학습.
6. test 250장 예측 → ID 기준 정렬 → CSV 저장·재읽기 검증 → 노트북 실행 결과 저장.

## 7. 완료 검증

- 입력과 특징 행 순서가 일치하고, 특징 shape=(750,1280)/(250,1280), NaN/Inf 없음.
- 학습/검증/확인 인덱스가 규칙대로 분리되고 전처리 학습은 학습 인덱스만 사용.
- 지표는 항상 5개 클래스 Macro-F1. 개발 선택 점수와 확인 점수를 구분해 표시.
- CSV 열 순서 image_id,label, 250행, 정수 0~4, ID 중복·결측·누락·추가 없음, sample 순서 일치.
- CSV 재읽기 후 같은 조건 통과. test 정답 채점은 하지 않음.
- nbformat 검증, 코드 셀 실행 결과 저장, 미해결 실행 오류 없음. 실제 수행한 후보·실패·소요 시간을 남김.

## 8. 구현 전 사용자 검토 사항

1. 개발 600장 + 확인 150장, 개발 내부 3-fold 방식과 확인 결과로 재튜닝하지 않는 원칙.
2. 분류기 3종×C 2개 상한, near-tie에서 단순 모델 선택하는 기준.
3. 약점 보완은 실제 개발 OOF 오류를 근거로 보조 특징 12개 한 번만 비교하고 위 조건으로 채택.
4. 실제 잔여 시간에 따라 후보·보완을 생략하고 최종 5분을 보호하는 방식.

승인 전 모델 코드 작성·학습·예측은 진행하지 않는다.
