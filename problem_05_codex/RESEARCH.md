## 3. 기존 실행 흐름과 환경

- 기존 Notebook: CSV 읽기 → 제공 helper로 특징 추출 → 분류기 구현 빈 셀 → 제출 형식 확인.
- helper: RGB 변환 → bilinear 224×224 → ImageNet 평균/표준편차 정규화 → CPU ONNX 추론 → 1,280차원 float32 벡터. 전달한 경로 순서를 보존한다.
- 캐시는 모델·이미지 내용·전처리 서명에 따라 검증된다. 고정된 encoder 특징은 전체 데이터에서 미리 추출해도 학습 누수가 아니다. 스케일러는 별도로 각 학습 fold에서만 fit해야 한다.
- 클래스별 2장씩 10장 시험 추출: (10,1280), 모두 유한값, 세션 생성 포함 약 0.117초. 전체 추출 시간은 아직 측정하지 않았다.
- python3 사용, CPU 논리 코어 8개. numpy 1.26.4, pandas 2.3.2, sklearn 1.7.2, onnxruntime 1.23.2. nbformat/nbclient 이용 가능.
- SciPy가 NumPy 버전 호환 경고를 출력했다. import와 encoder 실행은 성공했으나 분류기 fit은 미확인이다. 승인 후 첫 기준 모델로 실행 호환성을 확인한다. GPU 탐색 경고와 무관하게 CPU encoder는 실행됐다.

## 4. 후보 비교 — 아직 성능 측정 전

공통 입력은 제공 특징에 fold 내부 표준화와 이미지별 L2 정규화를 적용한다. 전처리 선택 자체는 이번 예산에서 튜닝하지 않는다.

| 후보 | 역할 | 위험 및 제한 |
|---|---|---|
| L2 로지스틱 회귀 | 단순한 선형 기준선, 규제로 고차원 계수 제어 | 복잡한 클래스 경계를 놓칠 수 있음 |
| 선형 SVM | 선형 마진 기준의 대안 | 약한 클래스가 반드시 개선되는 것은 아님 |
| RBF SVM | 표현 공간의 비선형 경계 비교 | C·gamma 대규모 탐색은 선택 과적합 위험. gamma 고정, C 두 개만 |

C가 작을수록 규제가 강하지만, 서로 다른 알고리즘의 같은 C가 같은 규제 강도를 뜻하지 않는다. 각 후보는 동일 분할의 Macro-F1로 비교한다. 학습 정확도만으로 채택하지 않는다.

## 5. EDA에서 실험으로 연결

1. 750장의 균형 표본과 1,280차원 특징 → 고정 encoder + 규제 분류기, class_weight 없이 시작.
2. 유사한 식생 클래스 → 먼저 비선형 경계의 효과를 RBF SVM으로 비교.
3. 색상·질감 차이 → 조건부로 12개 보조 특징 한 묶음만 추가. 보조 특징의 가중치는 고정해 탐색 범위를 제한.
4. OOF 최저 F1·혼동 쌍을 진단하되, 특정 클래스만 올리고 전체 Macro-F1을 떨어뜨리는 수정은 채택하지 않음.
5. test 예측 비율 강제, 라벨 수정, 혼동 쌍 전용 모델, CNN 재학습, 다수 앙상블·증강 탐색은 이번 계획에서 제외.

과적합 방지는 성능 보장이 아니다. 규제·후보 수 제한·학습 fold 내부 전처리·확인용 holdout을 함께 사용한다. 전체 라벨로 수행한 EDA의 영향을 고려하면 holdout도 완전한 외부 독립 데이터는 아니다.
