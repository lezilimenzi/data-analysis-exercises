## P2: 공간 헤드와 이동 TTA

동일한 3개 convolution block 뒤의 GAP를 3×3×128 Flatten으로 바꿨다.
폭32·20 epoch·batch128·AdamW/OneCycleLR·학습 seed를 유지해 GAP/공간 헤드 18개 모델을 학습했다.
TTA는 원본·상하좌우 각 1픽셀 zero-pad 이동 5뷰의 확률 평균이다.
파라미터는 287,783→294,951(+2.49%)이다. 위치 정보와 파라미터 증가의 원인은 분리하지 않았다.

| 3-seed 앙상블 | OOF Macro-F1 | 오류 수 | 외투↔풀오버 | 기준 대비 고침/망침 |
|---|---:|---:|---:|---:|
| GAP 기준 | 0.960232 | 195 | 85 | — |
| GAP + TTA | 0.960876 | 192 | 86 | 27/24 |
| 공간 헤드 | 0.957062 | 211 | 98 | 41/57 |
| 공간 헤드 + TTA | 0.956019 | 216 | 101 | 41/62 |

기존 P2 판정 기준은 **9짝 평균 d≥.003, 개선≥6/9, 앙상블 비악화**다.
세 후보 모두 미통과이므로 문서상 권고는 기존 GAP+3-seed 유지다.
TTA에 아주 작은 평균 이득이 관측된 사실과 채택 실패를 구별한다.
공간 헤드에 TTA를 추가한 조건부 효과도 평균 −0.000083으로 이득을 확인하지 못했다.
공통 오류가 많다는 관측만으로 GAP의 공간 정보 손실을 원인으로 확정할 수 없었다.
다른 공간 헤드나 다른 TTA 전체가 무효라는 결론도 아니다.

GAP 기준의 과거 OOF는 세 seed 모두 예측 라벨·F1이 일치했다.
확률의 최대 절대 오차는 1.79e−7로, 확률까지 비트 수준으로 동일한 것은 아니다.
검증 fold당 GAP 평균 추론은 원본 0.786초, TTA 3.982초였다.
18개 학습의 fold당 평균은 GAP 87.5초, 공간 헤드 92.2초이며 실행 중 부하가 같지는 않다.
마지막 재개 실행은 약 26.8분이었고 첫 완료 모델 캐시 1개를 재사용했다. 중단된 실행 시간은 별도다.
[9짝](p2_pairs.csv), [클래스별 결과·혼동·비용·기준 재현](p2_summary.json),
[저장 OOF 재검산](verification.json)에 상세 수치를 남겼다.

## 확인한 것과 한계

- P1 원 RF+GB의 반복별 기준 점수 10개를 정확히 재현했다.
  순이득은 반복 예측 합계 FN 18개 감소·FP 6개 증가다. 결측 행 외의 예측도 바뀐다.
  앞선 RF 단독 +0.003325, 10/0/0과 이번 앙상블 결과를 구별한다.
- P3 원 시작점별 기준 MAE를 최대 절대 오차 약 1.8e−15로 재현했다.
  매월·각 24시간 horizon의 평균 MAE와 야간 승온 MAE가 개선됐지만
  일교차 오차는 3.327747→3.342557로 악화했다. MAE 감소는 약 0.23%다.
- P4 기존 1.4도 과거 같은 데이터에서 고른 값이다. 내부 선택 후보가 낮다고
  선택 절차 없이 임의 가중치를 고르는 방법이 더 정당하다는 결론은 아니다.
  순서 변경 쌍 두 개를 묶은 118그룹 검증도 실행했다. 같은 모델의 fold 평균은
  원 층화 분할 0.767346, 그룹 분할 0.771476이다. 평가 fold가 다르므로 개선량으로 계산하지 않는다.
  [그룹 진단](p4_group_diagnostics.json)은 큰 하락을 보이지 않았지만 실제 생성 관계를 증명하지 않는다.
- P5 원 고정 특징 캐시의 모델·이미지·전처리 서명을 확인했고, 앞선 기준 15개 점수를 재현했다.
  외부 가중치·fine-tuning 없이 제공 MobileNetV2만 사용했다.
  crop은 중앙 48×48(원 64×64의 75%) 한 개이며 다른 crop 전체의 실패를 뜻하지 않는다.
- P6 두 후보 모두 같은 바깥 그룹 분할이다. 안쪽 분할 방식만 달라진 비교이며,
  기존 무작위 바깥 CV 점수와 빼서 모델 개선량으로 해석하지 않는다.
  정규화 템플릿 3,989개는 실제 발신자·캠페인 식별자가 아니다.
  배포 목표가 새 템플릿이면 점수가 낮아져도 그 목표에 맞는 그룹 검증을 유지한다.
- P7 기준 pooled 점수 0.8538과 기존 정지 세션 L017/L018/L019의 FN/FP를 재현했다.
  새 블록은 기존 오류 3개를 고치고 새 오류 6개를 만들었다.
- P8은 [입력 스키마](p8_input_check.json)만 추가 확인했다.
  앞선 합성 시점 이동 스트레스는 상대 지연 후보의 효과 검증을 대신하지 않는다.

## 파일과 재현

- [p2_spatial.py](p2_spatial.py): 동일 CNN backbone의 GAP/3×3 헤드와 5-view TTA.
  fold별 `.pt`는 학습 가중치, `.npz`는 검증 인덱스·라벨·확률, `.json`은 비용·파라미터 수다.
  완료된 fold는 재사용하며 중단된 fold만 다시 학습한다.
- [tabular.py](tabular.py): P1/P3/P4/P7의 고정 후보.
- [image_text.py](image_text.py): P5/P6의 고정 후보. P5 crop 캐시도 내용 서명을 확인한다.
- [p4_group_audit.py](p4_group_audit.py): 순서 변경 쌍을 묶은 평가 민감도. 모델 선택에 사용하지 않는다.
- `pN_pairs.csv` / `pN_summary.json`: 반올림 전 짝별 점수와 판정.
- `pN_diagnostics.json`, `pN_oof*.npz`: 내부 선택·조건별 진단·train OOF.
- [verify.py](verify.py): 저장 OOF에서 보고 점수를 다시 계산하고 P6 그룹 분리 등을 검사한다.
- [verification.json](verification.json): P1~P7 모든 저장 점수·채택 판정, P4/P6 그룹 분리,
  P2 오류 고침/망침과 조건부 TTA 효과를 검산했다. 최종 실행 코드 해시도 포함한다.
- [manifest.json](manifest.json): 최초 코드·프로토콜·주요 입력 해시 및 환경.
  이후 P2 실행 진단 로그 추가는 프로토콜에 기록한다.
  P4 그룹 진단을 위한 입력 계산 함수 분리도 프로토콜에 기록했으며 계산식은 유지했다.
