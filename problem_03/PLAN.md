# PLAN — 72시간 시간별 기온 예측

> 상태: **완료 (2026-09-26). 최종 모델 M2-ridge (A 2.382, B 2.151) → submission.csv.**
> 근거 자료: `RESEARCH.md`. 목표: 시간 제약 없이 검증 MAE 최소화.

## 0. 요약

기본 구조 = **하루 주기 기준선 + 감쇠하는 이상치 보정**, 필요 시 **잔차 직접 회귀**, **소형 신경망(선택)**과 앙상블.
단순한 모델부터 올리고, 복잡한 모델은 쌍대 검증에서 명확히 이길 때만 채택한다.

## 1. 파일 구성 (신규 생성, 기존 파일 수정 없음)

| 파일 | 내용 |
|---|---|

- **누수 방지를 구조로 보장**: 하네스가 `hist = train[train.timestamp <= origin]` 만 모델에 넘긴다. 모델은 미래 데이터를 볼 방법이 없다.

## 2. 검증 하네스 (`evaluate.py`)

```python
FOLDS_A = 3일 간격 23:00 시작점: 2013-11-01~2014-02-25, 2014-11-01~2014-11-28   # 49개, 튜닝용
FOLDS_B = 3일 간격 23:00 시작점: 2014-12-01~2014-12-25                          # 9개, 홀드아웃
REC3    = [2014-12-19, 12-22, 12-25 23:00]                                      # 문제 권장, B의 부분집합

def evaluate(predict_fn, origins):
    for o in origins:
        hist = train[train.timestamp <= o]
        assert hist.timestamp.iloc[-1] == o
        y    = train.temperature_c[o+1h : o+72h]
        pred = predict_fn(hist); assert pred.shape == (72,) and isfinite
        mae[o] = mean(|pred - y|)
    return mae  # 구간별 Series
```

- 출력: 모델별 A 평균, **A1(2013-11~2014-02, 40개) / A2(2014-11, 9개) 평균**, B 평균, REC3 평균, horizon 구간(1–24/25–48/49–72)별 MAE, 기준 대비 **A에서 이긴 구간 비율**.
- **하네스 검증**: RESEARCH 4절의 기준 수치 재현 (A: persist 4.20, hm1 3.16, hm3 2.88 / REC3: persist 4.08, rep24 2.81, hm7 2.30). 불일치 시 진행 중단.

## 3. 후보 모델 (`forecast.py`)

### M0. 기준선
- `persist`, `hour_mean(k)` (k ∈ {1,3,5,7}).
- **현재 기준 = hm5 (A 2.86)** — 이후 모델은 이것과 비교.

### M1. 하루 주기 + 이상치 감쇠 (1순위)
```python
D       = hist 기온을 (days, 24) 행렬로 reshape       # 23:00 시작점이라 마지막 행이 완전한 하루
profile = D[-k:].mean(axis=0)                         # 24시간 모양 + 수준
anom    = mean(D[-1, 24-m:] - profile[24-m:])         # 최근 m시간 평균 이상치
pred[h] = profile[(h-1) % 24] + anom * alpha**h       # h = 1..72
```
- 파라미터: k ∈ {2,3,4,5,7}, m ∈ {1,3,6}, alpha ∈ {0.80,0.85,0.90,0.93,0.95,0.97,0.99}. 총 105개 조합, A에서 grid search.
- 변형 M1b: 모양은 긴 기간(k_shape ∈ {7,14})의 평균을 제거한 profile, 수준은 짧은 기간(k_level ∈ {1,2,3})의 평균. A에서 M1보다 나을 때만 채택.

### M2. 잔차 직접 다중 시점 회귀 (2순위)
- **샘플**: 23:00 시작점만 사용(test와 동일). 일 d의 끝을 시작점으로, 정답은 일 d+1..d+3의 72시간.
- **경계 규칙**: 검증 시작 일 D에 대해 학습 샘플은 d+3 ≤ D 인 것만 → 72개 정답 모두 hist 안.
  `assert` 로 확인.
- **목표**: `y[d, h] − base[d, h]`. base = M1 최적 설정의 예측 (없으면 hm-k profile).
  → 계절 수준이 빠져 연중 데이터를 학습에 쓸 수 있다.
- **특징** (모두 시작점까지의 값, 샘플 × h 행으로 펼침; 약 700 × 72 ≈ 5만 행):
  - 시점 공통: 마지막 24h 기온 이상치(24개, T − profile), 24/72/168h 평균 기온, 현재 T−Td, 24h 평균 T−Td,
    기압 현재값, 기압 변화 3/12/24h, 이슬점 변화 24h, 일교차(마지막 하루 max−min), 연중일 sin/cos
  - horizon별: h, 목표 시각 hour sin/cos
- **모델**:
  - M2-ridge: `StandardScaler + Ridge(alpha ∈ {0.1,1,10,100})`, 스케일러는 fold의 학습 샘플에만 fit(Pipeline).
  - M2-gbm: `HistGradientBoostingRegressor`, loss ∈ {squared_error, absolute_error},
    max_iter ∈ {200,500}, learning_rate 0.05, max_leaf_nodes ∈ {15,31}, min_samples_leaf 50. 조합 16개 이하.
- **학습 범위 비교**: 연중 전체 vs 시작점 연중일 ±60일 창(겨울만). A에서 비교해 하나 선택.
- 매 fold 재학습 (49+9회). 비용이 크면 결과표에 소요 시간 기록만 하고 그대로 진행.

### M4. 소형 신경망 잔차 모델 (선택 후보, PyTorch CPU)
- **목표·샘플·경계 규칙은 M2와 동일**: 23:00 시작점, 목표 = `y − base`, 학습 샘플은 d+3 ≤ D (`assert`).
- 샘플 단위는 시작점 1개 → **72개 잔차를 한 번에 출력** (다중 출력).
- 변형 2가지:
  - M4-mlp: 입력 = M2의 시점 공통 특징 벡터. `Linear → ReLU → Dropout(0.1) → Linear(72)`, hidden ∈ {64, 128}.
  - M4-lstm: 입력 = 최근 168시간 시퀀스 (기온 이상치, T−Td, 기압 변화) + 연중일 sin/cos. `LSTM(hidden ∈ {32, 64}, 1층) → Linear(72)`.
- 학습: L1 손실, Adam lr 1e-3, batch 64, 최대 200 epoch.
  - early stopping: fold 학습 샘플 중 **시간상 마지막 10%**를 내부 검증으로 떼어 사용 (patience 20). 이 내부 검증도 경계 규칙을 따름.
  - 입력 정규화는 내부 학습 샘플에만 fit.
- 결과 변동을 줄이기 위해 **seed 5개 평균**을 예측으로 사용. seed 고정으로 재현 가능하게 함.
- 매 fold 재학습 (58 fold × 5 seed × 조합). 비용은 결과표에 기록.

### M3. 앙상블
- 채택 규칙을 통과한 모델 중 상위 2개의 가중 평균: `w * 1위 + (1−w) * 2위`, w ∈ {0.3, 0.5, 0.7}. A에서 w 선택.

## 4. 선택 규칙 (A에서만 튜닝, B는 확인용)

1. 각 모델 계열의 파라미터는 **A 평균 MAE**로만 선택.
2. 복잡한 모델 채택 조건 (단순한 쪽과 쌍대 비교):
   - A 평균 MAE가 **0.05°C 이상** 낮고, **A 구간의 60% 이상(49개 중 30개 이상)에서 승리**.
     (실력이 같은 두 모델이 우연히 30개 이상 이길 확률은 약 8% — 정규근사)
   - B 평균이 단순 모델보다 **0.1°C 넘게 나빠지면 채택하지 않음** (B는 9개뿐이라 참고 수준).
   - A1은 학습 이력이 1년 미만이라 M2·M4에 불리할 수 있음 → A2·B 추세를 함께 보고한다.
3. 조건을 못 넘으면 단순한 쪽 유지. 비교 순서: hm5 → M1 → M2 → M4 (각각 그때까지의 최선 모델과 비교) → M3.
4. B 결과를 보고 다시 튜닝하지 않는다 (홀드아웃 오염 방지). 최종 후보 결정 후 B 결과를 보고.

**예외 기록 (2단계 결과 후 사용자 결정):** M1(k=5, m=1, α=0.97)은 hm5 대비 A −0.187°C였으나 승률 59.2%(29/49)로 60% 기준에 1개 미달. 개선이 1~24h에 집중되어 먼 horizon의 무승부성 잡음이 승률을 낮춘 점, 쌍대 t-검정 p=0.007 / Wilcoxon p=0.019를 근거로 **사용자 결정으로 채택**. 이후 모델은 M1과 비교한다.

**결과 기록 (3~4단계):** M2-ridge(α=1, 연중) A 2.382, M1 대비 −0.289 / 승률 65.3% → 채택. M2-gbm A 2.532(승률 59.2%, ridge보다 나쁨) → 탈락. M4-mlp A 2.459/2.478(h128/h64), M4-lstm A 2.557/2.531(h32/h64, ridge 대비 승률 46.9%/44.9%) → 탈락. 단, A2(9개)에서는 lstm64 2.355 < ridge 2.483 — A1의 짧은 학습 이력 영향 가능성. 규칙상 탈락 유지. LSTM 1차 실행은 세션 종료로 중단되어 재실행함.

## 6. 구현·검증 순서

1. `evaluate.py` 하네스 + M0 → verify: RESEARCH 4절 수치 재현
2. M1 grid search → verify: A 결과표, 최적 파라미터, hm5 대비 쌍대 비교
3. M2 (ridge, gbm) → verify: 경계 assert 통과, A 결과표, M1 대비 쌍대 비교
4. M4 (mlp, lstm) → verify: 경계 assert 통과, seed 간 MAE 편차 출력, A 결과표, 그때까지 최선 모델 대비 쌍대 비교
5. M3 앙상블 → verify: A 결과표
6. 최종 후보의 B / REC3 결과 보고 → 사용자 확인 후 선택 확정
7. `make_submission.py` → verify: `save_submission` 통과, 5절의 확인 항목 출력

## 10. 사후 검증 계획: 학습 샘플 단위 (2026-09-28, 승인 후 1·2단계 실행 완료)

### 10.1 배경과 질문
- M2의 학습 샘플은 **하루에 1개**(23:00 시작점)다. 17,448시간(727일)에서 앞 6일(168시간 특징 계산 불가)과 뒤 3일(72시간 정답이 train 밖)을 빼 최종 학습 때 718개였다. 72시간 정답이 이웃 샘플과 이틀씩 겹치므로 독립적인 정보는 이보다 적다.
- 8절에서 매시간 시작점(샘플 약 24배)은 "M2가 샘플 부족으로 보일 때만 재논의"로 미뤘고 시험하지 않았다.
- **질문**: 학습 샘플 수가 M2(ridge, gbm)의 병목인가? 병목이라면 매시간 시작점으로 늘리면 좋아지는가?
- 샘플이 병목일 수 있다는 신호: A2(학습 이력 약 2년)에서 LSTM64가 ridge보다 좋았다(2.355 대 2.483, 9구간).
- 병목이 아닐 수 있다는 신호: ridge가 벌점 세기 0.1~10에서 거의 같은 결과(2.390~2.410)를 냈다.

### 10.2 범위
- **목적은 전략 학습이다.** 최종 제출(`submission.csv`, 채점 MAE 2.156)은 바꾸지 않고, 새 제출 파일도 만들지 않는다. 정답·출제자 폴더는 사용하지 않는다.
- 기존 파일(`forecast.py`, `evaluate.py`, `make_submission.py`, `logs/`의 기존 결과)은 수정하지 않는다. 새 스크립트만 추가한다.
- 검증 구간은 기존과 같다: 튜닝 A(49), 홀드아웃 B(9). **평가 시작점은 계속 23:00만** 쓴다 (test와 같은 조건).
- 실행은 problem_02 학습 설정 검증이 끝난 뒤에 한다 (CPU 경합으로 둘 다 느려지는 것을 피함).

### 10.3 1단계 — 학습 곡선 진단 (`exp_learning_curve.py`)
- 기존 23:00 샘플을 그대로 쓰되, 각 검증 시작점에서 쓸 수 있는 학습 샘플 중 일부만 **무작위로** 뽑아 학습한다.
  - 비율: 25%, 50%, 75%, 100%
  - 25~75%는 서로 다른 무작위 추출 3회(seed 0, 1, 2)의 평균과 편차를 낸다. 100%는 추출이 없으므로 1회.
  - 가장 최근 일부만 쓰는 방식은 학습 기간과 계절 구성이 함께 바뀌어 샘플 수 효과와 섞이므로 쓰지 않는다.
- 모델: M2-ridge(α=1, 연중), M2-gbm(기존 최선: squared_error, 200회, 31 leaves, 연중). 둘 다 `forecast.residual_data`의 특징·목표를 그대로 쓴다.
- 출력: 비율별 A / A1 / A2 평균 MAE (± 추출 간 편차), 시간대별(1–24, 25–48, 49–72h) MAE.
- 비용: ridge는 수 분으로 예상. **gbm은 미측정**이다. 첫 시작점에서 시간을 재고, 전체가 60분을 넘을 것 같으면 gbm은 추출 1회로 줄이고 그 사실을 기록한다.
- **2단계 진행 판정 [임계값, 결과를 보기 전에 고정, 사용자 수정 가능]**: 모델별로
  1. 100%의 A MAE가 75%보다 **0.02°C 이상** 낮고,
  2. 50% → 75%에서도 개선이 있으면

  "곡선이 아직 내려가는 중(샘플 병목)"으로 보고 그 모델에 대해 2단계를 한다. 둘 다 해당하지 않으면 2단계를 하지 않고 "샘플 수는 병목이 아니었다"로 기록한다.

### 10.4 2단계 — 매시간 시작점 학습 (`forecast_hourly.py`, `exp_hourly.py`, 1단계 판정 통과 시에만)
- **학습 시작점**: 모든 시각 o 중에서 과거 168시간이 있고 **o + 72h ≤ 검증 시작점 c**인 것. 행마다 `assert`로 경계를 강제한다. 평가 시작점은 23:00 그대로.
- **기준선 M1을 임의 시각으로 일반화**:
  - profile = o 직전 k×24시간(k=5)을 시계 시각(0~23시)별로 평균한 값
  - anom = T(o) − profile[hour(o)]
  - pred(h) = profile[hour(o + h)] + anom × 0.97^h
  - o가 23:00이면 기존 M1과 **완전히 같아야 한다** (검사 항목).
- **특징**: 기존 37개를 임의 시각으로 일반화한다. "마지막 24시간 이상치 24개"는 시계 시각 순서가 아니라 o로부터의 시차 순서로 둔다(23:00에서는 두 순서가 같다). 일교차는 마지막 24시간의 최고−최저. 여기에 **시작 시각의 sin/cos 2개**를 추가해 39개.
- **모델** (후보 수 제한):
  - ridge: α ∈ {1, 10, 100} (샘플이 늘면 최적 벌점이 달라질 수 있으므로 3개만)
  - gbm: 기존 최선 설정 1개. 1단계에서 gbm이 판정을 통과한 경우에만. 행 수가 약 24배(스택 시 약 120만 행)라 시간을 먼저 측정한다.
- **비교 대상과 채택 규칙**: 현재 최종 모델 M2-ridge(23:00 샘플)와 같은 A 구간으로 짝지은 비교. 기존 4절 규칙을 그대로 쓴다.
  - A 평균 MAE가 **0.05°C 이상** 낮고, **A 49구간 중 60% 이상에서 승리**
  - B 평균이 **0.1°C 넘게** 나빠지면 기각
  - 4절 예외 기록(M1 채택)의 교훈에 따라 쌍대 t-검정과 Wilcoxon p값도 **함께 보고**한다. 다만 판정 규칙 자체는 바꾸지 않는다.
- **필수 검사**
  1. 23:00 시작점에서 일반화한 M1과 특징이 기존 `forecast.m1`, `origin_features`와 일치한다 (허용 오차 1e-9).
  2. 모든 학습 행의 72시간 정답이 검증 시작점 이전에 끝난다.
  3. 검증 시작점 이후 데이터를 999로 바꿔도 예측이 바뀌지 않는다.
  4. 학습 행 수가 예상(시작점까지의 시간 수 − 168 − 72 부근)과 맞는다.

## 11. 사후 검증 계획 2: 시간대 혼합(H1)·시작 시각 가중치(H2) (2026-09-28, 실행 완료: H1·H2 기각, H3 미진행)

### 11.1 배경과 원칙
- §10 2단계에서 매시간 시작점 ridge는 A 평균으로 개선이 없었다. 다만 가까운 시간(1–24h)은 나빠지고 먼 시간(49–72h)과 학습 이력이 긴 A2·B는 좋아졌다.
- 아래 가설은 **A·B 결과를 보고 만든 것**이다. 그래서 A는 설정 조정에만 쓰고, 판정은 **어떤 선택에도 쓰지 않은 새 평가 구간 C**에서 한 번만 한다.
- 목적은 전략 학습이다. 제출 파일은 바꾸지 않고, 정답·출제자 자료는 쓰지 않는다.

### 11.2 평가 구간
- **C (판정용)**: 2014-03-01 ~ 2014-10-28의 23:00, 3일 간격(81개). 72시간 평가 구간이 A2(2014-11-02~) 이전에 끝난다. 학습 이력은 14개월 이상이다.
- C0 (참고): 2013-03-01 ~ 2013-10-28의 23:00, 3일 간격. 학습 이력이 짧아(2~10개월) 판정에는 쓰지 않는다.
- A (조정용), B (참고): 기존과 같다.
- C의 한계: 겨울이 아니다. C에서의 결과는 "구조가 일반적으로 도움이 되는가"의 근거이지 겨울 test의 보장이 아니다. EDA는 train 전체로 했으므로 C도 완전히 본 적 없는 자료는 아니다(평가·선택에는 쓰지 않았다).

### 11.3 후보 (결과를 보기 전에 고정)
- 기준: `daily_ridge1` (23:00 샘플, 특징 37개, α=1) = 최종 M2-ridge.
- 매시간 ridge의 α는 §10 2단계에서 A 최선이었던 **α=10**으로 고정한다.
- **H1 시간대 혼합**: 1~H0시간 뒤는 `daily_ridge1`, 그 이후는 `hourly_ridge10`의 예측을 쓴다. H0 ∈ {24, 48}.
- **H2 시작 시각 가중치**: 매시간 샘플, 특징 39개, ridge α=10. 학습 가중치는 w = exp(−d²/(2σ²))이고 d는 시작 시각과 23시의 원형 거리(0~12시간)다. σ ∈ {1, 3, 6}. 가중치는 정규화하지 않는다. 스케일러는 가중치 없이 학습 행 전체로 맞춘다.
- 각 가설에서 **A 평균 MAE가 가장 낮은 설정 1개**만 C로 보낸다. 동률이면 앞의 후보(H0=24, σ=1)를 고른다.

### 11.4 판정 규칙 (C에서 한 번)
- 채택: C 평균 MAE가 기준보다 **0.05°C 이상** 낮고, **C 구간의 60% 이상**에서 기준보다 낮다.
- 보고(판정에 쓰지 않음): 시간대별(1–24/25–48/49–72h) MAE, 쌍대 t-검정·Wilcoxon p, B와 C0 결과, 참고용 `hourly_ridge10`의 C 결과.
- **H3 진행 조건**: H1 또는 H2 중 하나라도 C에서 채택 규칙을 통과하면 H3(매시간 샘플 GBM)를 별도 계획으로 진행한다. 둘 다 통과하지 못하면 H3는 하지 않고 가설을 닫는다.
- C에서 후보를 바꿔 가며 다시 평가하지 않는다.

### 11.5 구현과 검사
- 신규 `exp_hourly_mix.py`: `exp_hourly.py`의 `hourly_tables`, 원점·검사 로직을 재사용하고 가중치 학습을 추가한다. 기존 파일은 수정하지 않는다.
