## 0-1. 최종 모델 요약 (2026-09-21)

> EXPERIMENTS.md Run 1~5와 submission_01/02 채점 결과를 반영한 현재 채택 모델. 구현은 `train.py` 하나로 전체 재현 가능.

### 모델 아키텍처
- **알고리즘**: `sklearn.ensemble.HistGradientBoostingClassifier` (scikit-learn 1.7.2)
- **하이퍼파라미터**: 기본값 그대로 — `learning_rate=0.1, max_iter=100, max_leaf_nodes=31, min_samples_leaf=20, l2_regularization=0.0`. 4개 변형(min_samples_leaf/max_leaf_nodes 규제 강화, learning_rate 완화, l2 강화)을 CV로 비교했으나 유의미한 개선 없어 기본값 유지 (EXPERIMENTS.md Run 4)
- **class_weight**: `'balanced'`. CV상으로는 `None`과 mean_f1이 완전히 동일(0.8311)했지만, 실제 채점에서 개선(F1 0.8226→0.8372, +0.0146)되어 **사용자 판단으로 채택**한 예외 사항 — CV 근거만으로는 뒷받침되지 않는 결정임을 기록해둔다 (EXPERIMENTS.md 참고)
- **분류 임계값**: 0.5가 아닌 **0.732** (OOF 확률에서 F1을 최대화하는 지점을 반복 CV로 탐색해 평균)
- **랜덤 시드**: 42, 단일 시드. 시드 10개 평균(앙상블)을 CV로 검증했으나 효과가 정확히 0이라 미채택 (Run 5)

### 입력 피처 (8개)

| 피처 | 유형 | 비고 |
|---|---|---|
| equipment_grade | 범주형 (`category` dtype) | HGB `categorical_features='from_dtype'`로 원-핫 인코딩 없이 네이티브 처리 |
| ambient_temp_c | 수치 (원본) | 결측 있음, NaN 그대로 입력 |
| rotation_rpm | 수치 (원본) | feature importance 1위(0.314) — 단변량 AUC는 가장 낮았지만(0.223) 다른 변수와 결합 시 가장 중요 (U자형 비단조 관계) |
| torque_nm | 수치 (원본) | 결측 있음 |
| tool_usage_min | 수치 (원본) | 결측 있음 |
| power_w | 파생 = torque_nm × rotation_rpm × 2π/60 | feature importance 3위(0.198) |
| wear_x_torque | 파생 = tool_usage_min × torque_nm | feature importance 4위(0.170) |
| temp_diff | 파생 = process_temp_c − ambient_temp_c | feature importance 2위(0.304) |

**제외된 원본 변수**: `process_temp_c` — permutation importance ≈0(mean −0.002, std 0.014로 0과 통계적으로 구분 안 됨)이고, 제거해도 CV 성능 유지(오히려 근소 상승 0.8286→0.8311)되어 제거. ambient_temp_c와 상관 0.88로 중복 정보였고 temp_diff가 이미 그 차이를 뽑아내고 있었음.

**시도했으나 미채택**: 결측 지시변수 3개(ambient/torque/tool_usage_missing) — CV에서 효과 정확히 0 (raw_derived와 raw_derived_missing의 mean_f1 완전 동일, Run 1)

### 결측치 처리
- 별도 대체(imputation) 없음 — HGB가 학습/예측 시 NaN을 네이티브로 처리 (각 분할에서 결측값이 어느 쪽 가지로 가야 유리한지 데이터로부터 직접 학습)
- 파생 변수(power_w, wear_x_torque, temp_diff)는 입력 원본이 결측이면 자동으로 NaN 전파됨 — 이 역시 HGB가 네이티브 처리

### 학습/검증 방식
- **검증**: Stratified 5-fold × 10회 반복 CV. 매 반복마다 OOF(out-of-fold) 확률로 F1 최대화 임계값 탐색 후 그 반복의 최적 F1 기록. 10회 평균/표준편차로 설정의 안정성을 판단
- **모델·피처 선택 절차** (그리드가 아니라 순차적 조건부 검증, 다중비교 억제):
  1. 피처 3단계(raw/raw_derived/raw_derived_missing) × 모델 2종(로지스틱회귀 베이스라인/HGB) = 6개 config 비교
  2. 승자에 대해 process_temp_c 제거를 조건부 재검증
  3. class_weight='balanced'를 조건부 검증 (CV 동률 → 실채점 기준으로 사용자가 채택)
  4. 하이퍼파라미터 4개 변형을 조건부 재검증
  5. 시드 앙상블(n=10)을 조건부 재검증
- **선택 기준**: mean_f1이 가장 높은 config를 우선하되, 더 단순한 대안과의 차이가 표준편차 이내면 단순한 쪽 채택 (Simplicity First)
- **최종 학습**: 위 설정 확정 후 train 8,000행 전체로 1회 재학습

## 0. 범위와 전제

- 과제: 6개 입력(등급 1 + 수치 5)으로 `inspection_required`(0/1)를 예측. 평가지표는 **양성(1) F1**. 제출은 정수 0/1.
- 사용 도구: Python 3.11 **표준 라이브러리만** (pandas, scikit-learn 미설치). 상관, AUC, KS, 신뢰구간(Wilson)은 직접 계산했다.
- 재현: EDA 스크립트는 임시(scratchpad) 폴더에 있고 프로젝트에는 저장하지 않았다. 필요하면 `eda.py`로 저장한다.
- **연습 규칙**: problem.md 7절에 따라 원본 데이터 검색, 외부 정답 결합, 정답을 이용한 튜닝을 하지 않는다.
  - 사용자가 데이터 출처를 *AI4I 2020 Predictive Maintenance*(UCI)라고 알려주었다. 행 수 합계 10,000과 양성률 3.39%는 그와 부합하지만 **원본과 대조하지는 않았다.**
  - 원본에 알려진 고장 규칙과 임계값은 사용하지 않는다. 아래 파생 변수는 변수 설명(온도, rpm, 토크, 사용 시간)에서 나온 후보일 뿐이다.

### 2변수 상호작용 (양성/전체)

- **temp_diff × rpm**: rpm이 낮은 사분위(<1423)에서 temp_diff가 가장 낮은 사분위는 114/463 = **24.6%**, 나머지는 27~33/약 500 = 5~7%. 두 조건이 겹칠 때 양성률이 크게 오른다.
- **tool_usage × torque**: 사용시간 상위 사분위(>162)와 토크 상위 사분위(>46.8)가 겹치면 91/504 = **18.1%**, 사용시간이 낮아도 토크 상위면 34~38/약 490 = 7~8%. 토크가 높으면 사용시간이 위험을 추가로 높인다.
- 즉 조합 효과가 있어 상호작용을 학습할 수 있는 모델(트리 계열)이 유리할 가능성이 크다. 확인은 CV로 한다.

| 4 | 결측 1%, 결측-라벨 관계 불명 | NaN 직접 처리(트리) 또는 fold 내 대체. 결측 지시 변수는 CV로 효과가 있을 때만 채택 |
| 5 | 등급 효과 약함 | 유지하되, 제거해도 성능이 같으면 제거 후보 |
| 6 | 분포 이동 없음 | test 예측에 별도 보정 불필요 |
| 7 | 양성이 3.4%로 드묾 | 임계값이 0.5가 아닐 가능성이 큼. 먼저 임계값 조정만 시도하고, 부족할 때만 class_weight 검토 |

## 8. 미확인 사항 / 가정

- 모델을 하나도 학습하지 않았다. 위 시사점 2~5는 모두 **검증 전 가설**이다.
- 4절의 구간 경계(예: 1363 rpm, 52.6 N·m, 196분, 8.8 °C)는 train 관측값이며 노이즈를 포함한다. 양성이 5~20건인 세부 구간은 특히 불안정하다.
- 파생 변수의 물리적 의미(예: power = 토크 × 각속도)는 변수 설명에서 추론한 것이다. 이 데이터가 실제로 그 관계로 생성되었는지는 확인하지 않았다.
- 원본 데이터셋(AI4I 2020)의 존재는 사용자가 알려준 정보다. 원본과의 대조는 하지 않았다(규칙상 하지 않는다).
- 환경: pandas와 scikit-learn 미설치. 구현 단계에서 설치 여부를 사용자와 정해야 한다.
