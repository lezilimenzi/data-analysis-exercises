## 1. 목표와 성공 기준
- 산출물: `submission.json` (1,400 ID, 정수 라벨 0~6).
- 최종 지표: Macro-F1. 모델 선택은 CV로만 한다. test 점수로 튜닝하지 않는다.
- 성공 기준 (검증 전 희망치): 최종 구성의 3-fold OOF Macro-F1이 SVC 기준선 CV보다 fold 간 표준편차 이상 높고, 목표는 ≥ 0.95. 미달이어도 CV로 채택된 최선의 구성을 제출한다.
- **시간 예산**: 문제 풀이 전체 60분 (사용자 확인). 계산 시간 예상 약 40~45분이다. [가정] 이 60분은 계산 시간만이 아니라 전체 과정이지만, 코드 작성·디버깅이 포함되는지는 사용자가 아직 답하지 않았다. 여기서는 계산 시간만으로 예산을 짰다. 포함이라면 §6의 후퇴 순서로 더 줄인다.

## 4. 공통 규약 (`common.py`)
```python
def folds():  # 모든 실험 공통 3-fold, seed 0 고정
    return list(StratifiedKFold(3, shuffle=True, random_state=0).split(np.zeros(len(y)), y))
def mf1(y, p): return f1_score(y, p, labels=list(range(7)), average="macro", zero_division=0)
```
- 입력은 `load_train()`의 `/255` 값 그대로. 학습이 필요한 전처리(PCA 등)는 sklearn `Pipeline` 안에서 fold 학습 부분으로만 fit.
- 모든 실험은 fold별 Macro-F1, 평균, 표준편차, OOF 예측(확률 포함)을 `results/`에 저장한다. 모든 모델이 **동일 3-fold**를 쓰므로 짝지은 비교와 OOF 앙상블이 가능하다.
- 모든 스크립트는 단계별 경과 시간을 기록해 누적 계산 시간을 추적한다.
- test는 `final.py` 외에서 읽지 않는다.

## 5. 단계별 계획

### Step 1 — 전통 모델 3-fold (`exp_classical.py`, 예산 10분)
| 모델 | 설정 |
|---|---|
| LR | `LogisticRegression(C=1, max_iter=500)` |
| kNN | k=5, `weights="distance"` |
| SVC-RBF | C=10 × gamma ∈ {scale×0.5, scale, scale×2} (3개) |
| RF | 300 트리 |
| HistGradientBoosting | `max_iter=100`, `learning_rate=0.1` |
| MLP | `MLPClassifier((512,256), early_stopping=True, max_iter=100)` |
| HOG+SVC | `skimage.feature.hog(orientations=9, pixels_per_cell=(7,7), cells_per_block=(2,2))` 324차원, SVC(C=10, gamma=scale) |
| PCA+SVC | Pipeline(PCA(100), SVC(C=10, gamma=scale)) |

- fold 단위 `joblib` 병렬 (n_jobs=3).
- **시간 상한 [임계값]**: Step 1 전체 10분. 한 설정이 3분을 넘으면 중단하고 그 설정은 "시간 초과"로 기록한다 [3분은 가정]. 사용자가 정한 "설정당 20분"은 전체 60분 예산에 맞지 않아 폐기했다.
- 확인: 기준선 SVC(3-fold)가 EDA 단일 분할 0.9387에서 크게 벗어나지 않는지 (3-fold는 학습이 작아 소폭 낮을 수 있음).

### Step 2 — CNN 스크리닝 (`exp_cnn.py`, 3-fold, 예산 16분)
아키텍처 (고정): 블록 3개 (폭 32→64→128, 각 블록 Conv3×3-BN-ReLU 2회 + MaxPool 2), GAP, Dropout 0.3, Linear 7. 약 28.8만 파라미터.
학습: AdamW (lr 2e-3, weight_decay 1e-2), OneCycle, 배치 128, **20 epoch**, seed 0, `torch.set_num_threads(8)`. **마지막 epoch 모델**로 평가 (early stopping 없음).
증강 (학습 배치에만, 온라인):
```python
def shift(x, k=2):  # 샘플별 무작위 이동, 빈 공간은 0
    p = F.pad(x, (k,k,k,k)); dx, dy = randint(0, 2*k+1, (2, B))
    return stack([p[i,:,dy[i]:dy[i]+28, dx[i]:dx[i]+28] for i in range(B)])
def erase(x):  # 4~10px 정사각형을 0으로, 확률 0.5
def flip(x): torch.where(rand(B)<0.5, x.flip(3), x)   # 수평만
```
설정 (**4개**, 각 약 4분 [추정]: 3-fold의 학습 약 3,267장 × 20 epoch에 증강 오버헤드 10~30% 가산):
| # | 설정 |
|---|---|
| C0 | 증강 없음 (기준) |
| C1 | +shift |
| C2 | +shift+flip (신발 방향 정렬 위험 확인) |
| C3 | +shift+erasing |

- **채택 규칙 [임계값, 사용자 확정]**: C0 대비 짝지은 fold 차이의 평균 ≥ +0.3%p이고 3개 fold 중 2개 이상에서 양(+)이면 채택. 여러 개가 채택되면 평균이 가장 높은 것을, 없으면 C0를 쓴다. 증강 조합의 상호작용은 시험하지 않는다.
- label smoothing, epoch·lr 조정, 폭 64 시험은 시간 때문에 **생략**한다.
- 저장: OOF softmax (4,900×7)와 fold별 점수. 증강 오버헤드(초/epoch) 기록.

### Step 3 — 앙상블 평가 (`exp_ensemble.py`, 예산 약 3분)
- 재료: 3-fold OOF 확률. SVC는 최선 설정에서 `probability=True`로 OOF 확률 생성 (내부 CV로 시간이 늘 수 있음, 미측정. 3분을 넘으면 `decision_function` 소프트맥스로 대체하고 기록한다).
- 후보: (a) CNN 단독, (b) CNN+SVC 균등 평균, (c) (b)+Step 1 상위 다른 계열(HGB, MLP 등) 균등 평균. 모델 수 4개 이하.
- **가중치는 균등으로 고정, 튜닝하지 않는다.** 평균 CV Macro-F1이 CNN 단독보다 fold 표준편차 이상 높을 때만 앙상블을 채택한다.
- CNN 시드 앙상블의 효과는 계산 시간 때문에 **검증하지 않는다**. 최종에서 3 seed 평균을 쓰지만 그 이득은 일반적 경험에 기댄 가정이다.

### Step 4 — 최종 학습과 제출 (`final.py`, 예산 약 7분)
1. 선택된 구성을 **전체 4,900장**으로 재학습. epoch는 20 고정. CNN은 seed 3개, 앙상블이 채택되면 SVC 등도 재학습.
2. `X_test`의 확률 평균으로 라벨 예측 → `save_submission(image_ids, preds, "submission.json")`.
3. 자동 점검 (실패 시 예외):
   - ID 집합 = `sample_submission.json`의 ID 집합, 개수 1,400, 중복 없음
   - 각 label이 JSON 정수, 0~6
   - 예측 클래스 분포 출력 (클래스당 약 200개에서 크게 벗어나면 경고; test 균형은 미확인 가정)
4. 문서 요구 사항용 **80:20 stratified 분할(random_state=0) 점수 1회** (예산 약 5분): 최종 구성으로 80%만 학습해 20%를 채점하고 보고한다.
5. `results/summary.md`에 최종 모델, 검증 Macro-F1, 시도한 개선, 생략한 항목을 기록한다.

## 7. 트레이드오프 (압축안 A의 대가)
- **5-fold 재확인 생략**: 3-fold는 fold당 학습 크기가 작고 추정이 불안정하다. 3-fold의 설정 간 순위가 맞다는 [가정]을 검증하지 못한다.
- **시도 축소**: label smoothing, epoch·lr, 폭 64를 시험하지 않아 CNN의 잠재 성능을 덜 끌어낸다.
- **탐욕적 채택**: 증강 조합의 상호작용을 놓칠 수 있다.
- **마지막 epoch 사용**: 최적 epoch를 놓칠 수 있으나 최종 재학습과 일관성은 유지된다.
- **균등 가중 앙상블**: 최적이 아닐 수 있으나 튜닝에 따른 선택 편향을 피한다.
- **skimage 설치**: 표준 HOG를 쓰는 대신 user site의 scipy가 바뀐다. 설치 후 기존 import를 재확인한다.

## 8. 가정과 위험
- [위험] 여러 설정을 CV로 고르므로 최종 CV 점수는 낙관적이다. 80:20 점수는 같은 데이터로 선택한 뒤 산출하므로 **독립적인 일반화 성능이 아니다**. 진짜 일반화 성능은 test 채점에서만 알 수 있고, 그 결과로 다시 튜닝하지 않는다.
- [위험] 3-fold 검증 크기는 fold당 약 1,633장이라 표준오차가 약 ±0.6%p [추정, 이항 근사]이고, +0.3%p 채택 임계값은 잡음과 같은 수준이다. 그래서 채택 규칙은 "3개 중 2개 fold 양(+)"을 함께 요구하지만, **작은 개선은 구분되지 않을 수 있다**.
- [위험] 수평 뒤집기가 CV에서 좋아 보여도 test에 반영될지는 보장되지 않는다 (신발 방향 정렬).
- [위험] 재현성: torch CPU 연산의 비결정성으로 같은 seed에서도 소폭 차이가 날 수 있다. seed와 설정을 결과 json에 저장한다.
- [위험] 시간 추정 오차: 증강 오버헤드와 SVC 확률 생성 시간이 미측정이다. 첫 CNN 설정(C0, C1)의 실측으로 예산을 재계산한다.

## 9. 중단·후퇴 조건
- Step 2 결과 CNN이 SVC(3-fold)보다 fold 표준편차 이상 높지 않으면 CNN 추가 투자를 멈추고 앙상블(SVC+CNN+기타) 중심으로 간다.
- 어떤 Step이든 예산을 넘으면 사용자에게 알리고 §6의 후퇴 순서를 따른다 (임의로 설계를 바꾸지 않는다).
- 방향 자체가 틀렸다고 판단되면 결과 파일을 보존하고 이 계획을 수정해 재승인을 받는다.

## 11. 확정된 결정 (사용자 검토 반영)
1. 채택 임계값: +0.3%p 이상, 3개 fold 중 2개 이상 양(+).
2. 60분은 문제 풀이 전체 시간 → 압축안 A 채택. 기존 "설정당 20분" 상한은 폐기하고 Step 1 전체 10분으로 대체.
3. Step 1 그리드: 압축안에 맞춰 SVC 3개 설정 외에는 각 1개로 축소 (사용자가 원 그리드를 승인했으나 시간 예산 때문에 줄였다. 이견이 있으면 알려 달라).
4. 80:20 점수: 산출한다 (독립적 일반화 성능이 아니라는 한계 명시).
5. git: 사용하지 않고 `results/` 파일로 관리.
6. skimage: 설치한다 (§2의 numpy 고정 명령으로).

**미확인**: 60분에 코드 작성·디버깅 시간이 포함되는지. 포함이라면 §6의 후퇴 순서를 처음부터 적용해야 한다.

7. 시간 기준: 사용자가 현재 버전(계산 시간 기준 예산)으로 가도 된다고 확인했다.
8. 실험 결과는 EXPERIMENTS.md에 정리하고, 결과에 따라 PLAN.md를 수정한다.

| 시드 앙상블 검증 | 생략 (가정) | **3 seed를 3-fold로 검증**, +0.29%p | Step 1~3이 계획보다 짧게 끝나 예산 여유 발생 (약 8.5분 사용) |
| 최종 구성 | CNN 3 seed (+SVC 조건부) | CNN C0 3 seed 단독 | 위 결과 |
| 총 계산 시간 | 약 40~45분 | 약 40분 | 예산 내 |
- 사용자가 승인한 시간·임계값 기준은 변경하지 않았다. 추가된 실험(SVC C 그리드, 시드 검증)은 예산 안에서 가정을 검증하기 위한 것이다.
- skimage 설치: 계획대로 `pip install --user scikit-image "numpy==1.26.4" "pillow==9.0.1"` 실행. 실제로는 scikit-image 0.22.0 등만 설치되고 **scipy(1.8.0), numpy, sklearn, torch는 바뀌지 않았다** (사전 검증에서 예상한 scipy 교체는 발생하지 않음).

## 13. 후속 개선 계획 (오류 분석 기반, 사용자 승인: "1, 2번 확인")
배경: 3-seed OOF 오류 195건 중 외투↔풀오버 85건(약 44%), 운동화↔부츠 43건, 풀오버↔티셔츠 26건 (EXPERIMENTS.md §5).
남은 시간 예산 (60분 − 지금까지 약 40분 = 약 20분) 중 이 단계는 **최대 16분**으로 제한한다: Step 5 약 1분, Step 6 최대 8분, 채택 시 최종 재학습 최대 7분.

### Step 5 — 오류 분석 (`analyze_errors.py`, 학습 없음)
- 입력: 저장된 3-seed OOF 확률(`results/oof_proba_cnn_C0*.npy`)과 SVC OOF 예측. test는 읽지 않는다.
- 산출: 외투↔풀오버 오분류 이미지 몽타주 (`results/errors_coat_pullover.png`), 그리고 정량 지표:
  - 오류의 예측 신뢰도 (max softmax 평균)와 정답 클래스가 2순위인 비율
  - 3개 seed가 **모두** 틀린 이미지 수 (체계적 오류) 대 일부 seed만 틀린 수 (불안정 오류)
  - 같은 이미지를 SVC도 틀린 비율 (양쪽이 공통으로 틀리면 모델이 아니라 정보의 한계일 가능성)
- 판정 기준 [가정]: 3개 seed 모두 틀린 이미지가 오류의 대부분이고 SVC도 대부분 함께 틀리면 "정보 한계에 가까움"으로 보고 Step 6의 기대치를 낮춘다. seed 간 불일치가 크면 "분산 문제"로 보고 앙상블·정규화 쪽 후보를 우선한다.

### Step 6 — 외투/풀오버에 맞춘 개선 시도 (3-fold, 같은 fold, 예산 최대 8분)
비교 기준: C0 seed 0 (3-fold 0.9586, fold별 .9597 .9546 .9615). 모두 같은 seed 번호(fold)로 짝지어 비교한다.
| # | 후보 | 시간 [추정] | 근거 |
|---|---|---|---|
| 6a | label smoothing 0.1 (C0 + 손실 변경) | 약 4~5분 | 애매한 라벨(외투/풀오버)에 대한 과신 완화. 가설 |
| 6b | 외투/풀오버 전문 이진 분류기: 앙상블이 2 또는 6으로 예측한 샘플만 fold 학습 부분의 외투+풀오버로 학습한 CNN이 재분류 | 약 2~3분 (이진 학습 샘플이 적음) | 두 클래스만 집중 학습. 가설 |
- 시간 때문에 제외: 폭 64 (3-fold 약 12분), 40 epoch (약 8.5분), 입력 확대 (약 4배 비용).
- **채택 규칙 (기존과 동일)**: C0 대비 fold 차이 평균 ≥ +0.3%p이고 3개 fold 중 2개 이상 양(+). 추가로 외투·풀오버 F1이 하락하지 않아야 한다.
- 6a, 6b 모두 단일 seed 비교라 seed 간 편차(0.9559~0.9586)와 구분되지 않을 수 있다. **작은 개선은 채택하지 않는다.**
- 채택되면: 해당 구성을 전체 4,900장으로 seed 3개 재학습해 **새 파일 `submission_02.json`**으로 저장한다 (기존 제출 파일은 덮어쓰지 않는다). 시간이 부족하면 (80:20 재산출 없이) 재학습만 하고 그 사실을 기록한다.
- 채택되는 후보가 없으면 현재 제출 파일(CNN C0 3-seed)을 유지한다.
- 결과는 EXPERIMENTS.md에 이어서 기록한다.

### Step 5·6 실행 결과 (요약, 상세는 EXPERIMENTS.md §8)
- Step 5: 외투↔풀오버 오류의 약 68% (전체 오류의 69%)가 3개 seed 모두에서 반복되고 SVC도 대부분 같이 틀림 → "정보 한계에 가까움"으로 판정.
- Step 6: 6a label smoothing 평균 −0.04%p, 6b 전문 분류기 평균 −0.35%p (3개 fold 모두 하락). **둘 다 채택 규칙 미통과, 제출 파일 변경 없음** (`submission_02.json` 생성하지 않음).
- 실제 계산 시간: Step 5 약 1분, Step 6 약 5분 (예산 최대 16분 중). 누적 약 47분.

## 14. 사후 검증 계획: 학습 설정 (2026-09-28, 승인 후 실행 완료)

### 14.1 목적과 범위
- 최종 CNN의 학습 설정(epoch 20, lr 2e-3 등)은 관행값으로 고정했고 검증하지 않았다 (RESEARCH §0.4). 이 설정이 성능 병목이었는지 확인하고, 결과를 `../STRATEGY.md`의 전략에 반영한다.
- **목적은 전략 학습이다.** test 채점(0.9538)은 이미 끝났고, test 점수는 이 검증에 쓰지 않는다. 제출 파일(`submission.json`, `submission_01.json`)과 `final.py`는 바꾸지 않는다.
- test 파일은 읽지 않는다. 모든 비교는 train 4,900장의 기존 3-fold(`common.folds`) 안에서 한다.

### 14.2 비교 설계
- **기준**: 이미 저장된 C0 결과 3개 seed (seed = fold + 10×s, s = 0, 1, 2).
  - s0 .9597 .9546 .9615 / s1 .9627 .9515 .9578 / s2 .9603 .9542 .9533, 3-seed 앙상블 OOF 0.9602
- **새 설정도 같은 seed 3개로 돌린다** → fold × seed = 9쌍의 짝지은 비교. 기존 실험의 한계였던 "seed 1개 비교는 seed 편차(0.9559~0.9586)와 구분되지 않는다"를 줄인다.
- 한 번에 한 설정만 바꾼다.

| # | 설정 | 바꾸는 것 | 예상 시간 |
|---|---|---|---|
| E0 | 재현 확인 | C0 s0을 다시 실행해 저장된 fold 점수와 비교 (CPU 비결정성 확인), epoch별 곡선도 기록 | 약 4분 |
| E1 | epoch 40 | 20 → 40 (OneCycle 총 step도 함께 늘어남). epoch별 검증 Macro-F1 곡선 기록 | 약 26분 (3 seed) |
| E2a | lr 1e-3 | 최대 lr 2e-3 → 1e-3, 20 epoch | 약 12분 |
| E2b | lr 4e-3 | 최대 lr 2e-3 → 4e-3, 20 epoch | 약 12분 |
| E3 | (조건부) epoch 40 + shift 증강 | E1이 채택될 때만. 기준은 E1 | 약 27분 |

- 합계 약 54분, E3까지 약 81분. 백그라운드로 실행하고 `results/log.txt`와 결과 json으로 진행을 확인한다.
- epoch별 곡선은 fold의 검증 부분으로 계산하는 **진단용**이다. 곡선을 보고 epoch를 고르지 않는다 (고르면 검증 데이터로 튜닝하는 셈).

### 14.3 채택 규칙 (결과를 보기 전에 고정)
기준 C0 대비:
1. 9쌍(fold × seed) 차이의 평균 ≥ **+0.3%p**
2. 9쌍 중 **6쌍 이상**에서 양(+)
3. 3-seed 앙상블 OOF Macro-F1이 기준(0.9602)보다 낮지 않음

셋 다 만족하면 "개선"으로 판정한다. 참고로 Wilcoxon signed-rank p값도 보고하지만, 9쌍은 표본이 작아 판정에는 쓰지 않는다. 결과를 본 뒤 규칙이나 후보를 바꾸지 않는다.

### 14.4 코드 변경 (최소)
- `exp_cnn.train_predict`에 인자 2개를 추가한다. 기본값으로는 기존 동작이 그대로다.
  - `lr=2e-3`: AdamW와 OneCycle의 최대 lr
  - `on_epoch=None`: 매 epoch 끝에 모델을 넘겨받는 콜백 (곡선 기록용)
- 신규 `exp_train_settings.py`: E0~E3 실행, 결과 저장(`results/train_settings.json`, `results/oof_proba_ts_*.npy`, `results/curves_ts.json`), 채택 규칙 판정 출력.
- 기존 결과 파일(`cnn.json`, `cnn_seeds.json`, 기존 OOF)은 덮어쓰지 않는다.

### 14.5 검증 (완료 기준)
1. E0의 fold 점수가 저장된 값과 같거나 CPU 비결정성 수준(±0.2%p 이내)으로만 다르다. 크게 다르면 중단하고 원인부터 확인한다.
2. 모든 설정이 9개 fold 점수, 3-seed 앙상블 점수, 판정 결과를 출력한다.
3. 결과를 EXPERIMENTS.md §9에 표로 기록하고, 이 절 끝에 요약을 붙인다.
4. `../STRATEGY.md` 반영: 6.2절(학습 설정의 근거와 결과), 7절(레버 표), 12절(한계), 갱신 기록.
   - 개선이 없어도 "관행값이 이 데이터에서 충분했다"는 결과로 반영한다.

### 14.6 한계
- 3-fold, fold당 1,633장이라 개별 fold의 SE는 약 ±0.5%p다. 9쌍 비교로 줄였지만 +0.3%p 미만의 효과는 여전히 구분하기 어렵다.
- 한 번에 한 설정만 바꾸므로 설정 간 상호작용(예: 긴 학습 + 높은 lr)은 E3 외에는 보지 않는다.

### 14.7 실행 결과 (2026-09-28, 상세는 EXPERIMENTS.md §9)
- 사용자 결정: 기본안 범위(E0~E3), 새 제출 파일은 만들지 않음.
- E0: 저장된 C0 점수를 정확히 재현(차이 0).
- E1 epoch 40: −0.09%p, 4/9 → 기각. 그래서 E3(epoch 40 + shift)는 사전 규칙대로 실행하지 않았다.
- E2a lr 1e-3: −0.48%p, 0/9, Wilcoxon p = 0.004 → 기각 (명확히 나빠짐).
- E2b lr 4e-3: +0.11%p, 7/9, 앙상블 0.9602 → 0.9625, p = 0.129 → 기각 (기준 +0.3%p 미달).
- 결론: 기존 학습 설정(20 epoch, lr 2e-3)을 유지한다. 제출 파일과 `final.py`는 바꾸지 않았다.
- 코드 변경: `exp_cnn.train_predict`에 `lr`, `on_epoch` 인자 추가(기본값으로 기존 동작 유지, E0로 확인). 신규 `exp_train_settings.py`.
- 실제 계산 시간: 약 70분 (E0 약 5분, E1 약 33분, E2a·E2b 각 약 16분).
