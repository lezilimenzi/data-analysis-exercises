## 3. A·B 짝지어 비교 (7개 분할)

운전조건 군집은 KMeans(6)로 만들었습니다. 군집 크기는 train [632, 280, 163, 661, 10, 18], test [115, 34, 208, 81, 3, 0]이고, 평가에는 n≥20인 군집 4개만 썼습니다.

| 분할 | n | F1_A | F1_B | B−A | A 최소 여유 (샘플) |
|---|---|---|---|---|---|
| fit → valid | 440 | 1.0 | 1.0 | 0 | 2.0 |
| 저온(<45℃) → 고온(≥50℃) | 464 | 1.0 | **0.9432** | **−0.057** | 1.0 |
| 고온 → 저온 | 974 | 1.0 | 1.0 | 0 | 1.5 |
| LOGO 군집 0 | 632 | 1.0 | 1.0 | 0 | 3.0 |
| LOGO 군집 1 | 280 | 1.0 | 1.0 | 0 | 2.5 |
| LOGO 군집 2 | 163 | 1.0 | 1.0 | 0 | 1.5 |
| LOGO 군집 3 | 661 | 1.0 | 1.0 | 0 | 1.5 |

- [사실] B−A 평균은 −0.008이고, B가 앞선 분할은 0개, A가 앞선 분할은 1개입니다. 채택 규칙(PLAN §2)에 따라 **A를 채택**했습니다. 5조 (a)의 동점 판정 이전에, A가 짝지은 비교에서 우세합니다.
- [사실] **새로 발견한 점**: B(원시 파형 + RF)는 저온 데이터로 학습해 고온을 예측하는 분할에서 F1 0.943으로 떨어졌습니다. EDA의 군집 LOGO만으로는 이 약점이 보이지 않았습니다.
- [추론] RF는 파형 모양에 섞인 온도 관련 차이(진폭, 기울기)까지 학습하는 것으로 보입니다. 그래서 학습 범위 밖의 온도로 외삽할 때 흔들립니다. test는 고온 비율이 57%로 train(26%)보다 높습니다. 이 점에서 A를 주 모델로 둔 계획이 맞았습니다.
- [사실] 학습 분할에서 정한 경계를 기준으로 하면, A의 최소 여유는 고온 외삽에서 1샘플까지 줄어들었지만 오분류는 없었습니다. 이 여유는 정수 샘플 번호와 해당 분할에서 정한 경계 사이의 거리입니다.

## 4. test 진단 (정보 제공용, 제출에 영향 없음)

| 진단 | 결과 |
|---|---|
| 임계값 5 / 10 / 40 / 80 bar 예측과 A(20 bar)의 일치율 | 모두 1.000 |
| B(train 전체로 학습)와 A의 test 일치율 | 1.000 (불일치 0건) |
| 경계까지 여유 분포 (샘플: 건수) | 2.0: 3 / 3.0: 81 / 3.5: 10 / 4.0: 207 / 4.5: 94 / 5.5: 43 / 6.5~8.5: 각 1 |
| 여유 < 2샘플 | 0건 |

- [추론] train 전체로 학습한 B는 test에서 A와 100% 일치합니다. §3에서 B가 약했던 것은 학습 데이터에 고온 사이클이 없었던 경우에 한정된 것으로 보입니다.
- [추론] test에서 가장 불확실한 사례는 경계까지 여유가 2샘플인 3건입니다. 이 3건도 모든 임계값과 B에서 같은 클래스로 예측되었습니다.

## 5. 채점 결과와 사전 판단 대조

- [사실] test macro-F1 **1.0**, 441행 전부 정답입니다(사용자가 채점 결과를 전달).
- [사실] 채점 전에 근거로 삼은 세 가지가 결과와 맞았습니다.
  - 7개 분할 전부에서 A의 F1이 1.0
  - 임계값을 바꿔도, 모델을 바꿔도 test 예측이 같음
  - test 경계 여유가 2샘플 이상
- [사실] 경계 여유가 2샘플로 가장 작았던 test 3건도 정답이었습니다.
- [추론] adversarial AUC 0.99의 분포 이동이 있었지만, 라벨의 정의와 같은 물리량(밸브 전환 지연 → 압력 재상승 시점)을 100Hz 해상도로 쓰면 이동에 영향받지 않았습니다. 저해상도 범용 모델(1초 평균 RF, test 일치율 83%)을 썼다면 점수가 크게 떨어졌을 것으로 보입니다. 이 모델은 채점하지 않았으므로 미검증입니다.
- [추론] 0↔1 경계 간격(약 4.8샘플, 48ms)은 여전히 이 방법의 구조적 약점입니다. train에 없던 운전조건에서 상승 시점이 2샘플 이상 밀리면 오분류가 생길 수 있습니다. 이번 test에서는 문제가 되지 않았습니다.

## 6. 시험 운영 측면의 개선점 (점수 외)

검증 F1과 test 예측이 모든 방법에서 같았으므로, 점수를 올리는 추가 개선은 측정할 수 없습니다. 효과는 확인할 수 없고 버그 위험만 늘어나므로 시도하지 않습니다(CLAUDE.md 5조 (b)). 남는 개선은 시험 운영에 관한 것입니다.

1. **제출 시간 단축 (가장 실질적인 개선)**
   - 동점이면 제출이 빠른 쪽이 유리합니다(EXAM_GUIDE p.26). 1.0이 여럿 나올 수 있는 문제라면 순위는 제출 시간으로 갈립니다.
   - 시험장 순서:
     - (1) 로드, A, 저장의 핵심 셀 3개와 fit→valid F1 확인 1줄로 먼저 제출 가능한 상태를 만듭니다.
     - (2) 군집 LOGO, 온도 분할, B 비교, test 진단은 시간이 남을 때만 실행합니다.
   - 현재 노트북은 셀 13개입니다. 이 중 제출에 필요한 것은 로드, A, 저장 부분뿐입니다.
2. **실행 중단 대비 안전장치 (선택)**
   - 지금은 20 bar를 넘지 않는 사이클이 있으면 `assert`로 멈춥니다. 시험장 데이터가 조금 다르면 멈춤 자체가 시간 손실입니다.
   - 대안: 해당 사이클은 경고만 출력하고 B 예측으로 대체합니다(2~3줄 변경).
   - 현재 데이터에는 해당 사이클이 0건이라 결과는 바뀌지 않습니다. 구현하지 않았습니다.
3. **하지 않을 것**
   - 온도 보정, 선형보간 연속값, 경계 위치 최적화, 앙상블: 검증에서 차이를 만들 수 없고, 경계를 test에 맞추는 과적합 위험만 생깁니다.
   - B 개선 후 재비교: B는 교차 확인용이고, test에서 이미 A와 100% 일치합니다.
