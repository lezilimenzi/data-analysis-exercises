반복 fold는 행을 재사용하고 P3 목표도 겹치므로 독립 표본으로 보지 않는다.

- **P1**: 대체 전후의 관측값은 보존했다. 반복 예측 합계 고침/망침 36/21,

  8/10 개선 규칙도 통과했지만 독립 데이터·test 효과는 확인하지 않았다.
- **P2**: 같은 fold/seed의 저장 확률만 사용했다. 3seed ensemble F1 0.960232→0.960481,
  오류195→194, 고침/망침24/23. 앙상블을 쓰려면 두 구조가 필요하며 이번 .2초 실행은 저장 예측 평가 시간이다.

- **P4**: 개선 횟수가 더 많아도 악화 폭 때문에 평균은 낮았다. 반복 합계 고침35/망침39.

- **P6**: 고침6/망침11(3회 합계). 외부 템플릿 그룹은 분리했다. 기존 기준과 맞추기 위해

## P8: 합성 충격 잡음

clean fit1324개로 경계를 학습하고 valid440개를 평가했다. valid 중 고정132개(30%)의
900~919 위치에서 25bar 충격을 주입했다. 선택·위치는 seed20261009로 고정하며 라벨에 의존하지 않는다.

확인하지 않았다. 온라인 검출에서는 후보가 2표본을 더 관측해야 한다. 압력100Hz에서 추가 관측은20ms다.

## 재현·검산

설정·분할·판정 규칙은 [PROTOCOL.md](PROTOCOL.md), 코드 [run.py](run.py),
점수 재계산은 [verify.py](verify.py)에 있다. 실행 예:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 OMP_WAIT_POLICY=PASSIVE python3 strategy_round2_2026-10-09/run.py p1
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 strategy_round2_2026-10-09/verify.py
```

`run.py`는 p1~p8을 개별 실행한다. 기준 캐시가 있는 기존 작업 폴더가 필요하다.
결과는 `pN_pairs.csv`, `pN_summary.json`, `pN_oof*.npz` 또는 예측 NPZ,
`pN.log`, `pN_execution.json`에 보존했다. P8은 별도 `p8_stress.csv`다.
기준 점수·저장 예측·분할·그룹 경계·P3 학습 정답의 시간 경계·입력 해시·채택 판정을 재검산했고,
P8은 원 압력에서 충격 주입과 판정을 다시 구성했다. [검산 결과](verification.json).

문제별 실행 시간 합은 약383초다(P1 202.52초, P2 .20초, P3 7.02초, P4 29.12초,
P5 62.91초, P6 80.80초, P7 .48초, P8 .39초). 조사·문서·검산 시간과 이전 CNN 학습은 제외한다.
실행 환경·보조 파일 해시는 [environment.json](environment.json)에 기록했다.
기존 SciPy1.8.0/NumPy1.26.4 조합의 버전 경고가 로그에 있으나 실행 및 저장 점수 검산은 통과했다.
패키지는 변경하지 않았다.

`manifest.json`은 시작 시 입력·기준 캐시·프로토콜·코드·전략 문서의 해시다. 전략 문서는 이후 갱신됐고,
코드는 P3의 `numpy.str_`를 Python `str`로 바꾸는 한 줄 형식 수정만 했다.
[재개 기록](resume_2026-10-10.json)과 실행별 코드 해시로 P2의 수정 전 실행·나머지 수정 후 실행을 구분한다.
후보·분할·평가 규칙은 변경하지 않았다. 마지막 문서 상태는 `completion_checks.json`에 별도로 기록한다.
